### Название задачи:
ADR-002. Передача ставок в кол-центры.

### Автор:
Артур (ArtyrKa1300).

### Дата:
25.10.2026.

Дополнение к [ADR-001](../Task3/ADR-001-deposits.md), входит в MVP. Оба кол-центра должны консультировать клиентов по актуальным общим ставкам. Партнёр принимает файлы, API у него нет.

### Функциональные требования

| № | Действующие лица или системы | Use Case | Описание |
|---|---|---|---|
| CC-UC1 | Бэк-офис, АБС, адаптер, Kafka, сервис депозитов | Обновить ставки | 1. Бэк-офис утверждает версию в АБС. 2. Адаптер передаёт её через Kafka. 3. Сервис депозитов обновляет общий каталог. |
| CC-UC2 | Оператор и система кол-центра банка, API ставок | Проконсультировать клиента | 1. Оператор открывает ставки. 2. Backend получает их по HTTPS из сервиса депозитов. 3. Оператор видит условия и дату обновления. |
| CC-UC3 | Экспортёр, SFTP, система партнёра | Передать файл | 1. Экспортёр формирует файл общих ставок. 2. Загружает его на SFTP. 3. Партнёр проверяет и импортирует файл. 4. Возвращает файл подтверждения — ACK. |
| CC-UC4 | Оператор партнёра, внешняя система | Посмотреть ставки | 1. Оператор открывает локальный каталог. 2. Видит действующие ставки и время обновления. 3. Консультирует клиента. |
| CC-UC5 | Экспортёр, партнёр, эксплуатация | Повторить доставку | 1. При ошибке или отсутствии ACK файл отправляется повторно. 2. Партнёр не применяет одну версию дважды. 3. Повторные ошибки передаются поддержке. |

### Нефункциональные требования

| № | Требование |
|---|---|
| CC-N1 | АБС — источник утверждённых ставок; запросы операторов не нагружают её напрямую. |
| CC-N2 | Партнёру передаются только общие ставки, без данных клиентов и персональных предложений. |
| CC-N3 | Предложение: обновление в банке до 5 минут, у партнёра до 15 минут. Согласовать сроки с партнёром. |
| CC-N4 | HTTPS с авторизацией для API, SFTP с проверкой ключей и ограничением доступа. |
| CC-N5 | Файлы имеют версию, срок действия и контрольную сумму; применяются целиком. |
| CC-N6 | Формат CSV UTF-8 и правила обмена документируются. |
| CC-N7 | Контролируются доставка, ACK и просроченные ставки. |
| CC-N8 | Используются технологии и каталог из ADR-001. |

### Решение

Диаграммы: [контекст](context.drawio) ([SVG](context.svg)), [контейнеры](containers.drawio) ([SVG](containers.svg)), [компоненты](components.drawio) ([SVG](components.svg)).

Для банка используем **API**, для партнёра — **файлы через SFTP**. Выбор SFTP соответствует примеру RoadMap из задания; возможность подключения нужно подтвердить с партнёром.

Ставки утверждаются в АБС и через адаптер/Kafka попадают в сервис депозитов. Внутренний кол-центр запрашивает общий каталог по HTTPS. В своей системе он показывает условия и дату обновления.

В сервис депозитов добавляются компоненты: получение изменений ставок, API общего каталога, планировщик и экспортёр файлов. Экспортёр по расписанию формирует полный CSV: продукт, валюта, диапазон суммы, срок, ставка и период действия. Отдельный manifest содержит версию, дату и контрольную сумму.

Файл сначала загружается под временным именем, затем публикуется полностью. Партнёр проверяет версию и целостность, заменяет свой каталог и возвращает ACK. При повторной доставке версия не применяется второй раз. Несколько экземпляров экспортёра используют блокировку в БД, чтобы не выгружать одновременно.

SFTP разворачивается в выделенной зоне банка. Партнёр может читать ставки и оставлять подтверждения, но не получает доступ к АБС и внутренней Kafka. Просроченная или отозванная ставка не должна показываться как актуальная.

Работы по системам и сроки: [задачи](tasks.md), [RoadMap](roadmap.drawio) ([SVG](roadmap.svg)).

### Альтернативы

| Вариант | Почему не выбран |
|---|---|
| Прямой доступ к Oracle | Нагрузка на АБС и лишние права. |
| API или Kafka для партнёра | Партнёр готов только к файловому обмену. |
| Excel по почте вручную | Сложно контролировать версии, доставку и актуальность. |
| Отдельный новый сервис справочника | Дублирует уже созданный каталог депозитов. |

### Недостатки, ограничения, риски

- У партнёра ставки обновляются с задержкой.
- Нужно согласовать формат файлов и участие команды партнёра.
- Сбои SFTP требуют повторов и контроля поддержки.
- Общие ставки не заменяют согласование персональных условий.
