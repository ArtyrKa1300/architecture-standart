# Задание 2. Требования FURPS+

Рассматривается MVP на 6 месяцев. «Доп.» — дополнительные требования с обоснованием. Численные предложения нужно согласовать с банком.

| Код | Требования | Комментарий |
|---|---|---|
| **F** | **Функциональные** | |
| F1 | Сайт показывает депозиты и актуальные общие ставки. | Условие задания. |
| F2 | Клиент оставляет Ф. И. О. и телефон; заявка попадает в систему кол-центра. | Это обращение, а не открытый депозит. |
| F3 | Оператор звонит и может предложить особые условия; новый клиент проходит идентификацию в отделении. | Условие задания. |
| F4 | Интернет-банк показывает продукты, общие и персональные ставки клиента. | Депозиты и накопительные счета. |
| F5 | Клиент выбирает свой счёт, сумму и подтверждает заявку СМС-кодом. | Условие задания. |
| F6 | Кредитный и депозитный бэк-офис ведут и согласуют ставки с разделением прав. | Исходные данные отделов не раскрываются друг другу. |
| F7 | В MVP заявку обрабатывает менеджер в АБС. | Автоматизация — следующий этап. |
| F8 | Клиент получает СМС о подтверждении ставки и открытии депозита. | Два отдельных события. |
| F9 | Клиент видит номер и статус заявки. | Доп.: уменьшает повторные обращения. |
| F10 | АБС проверяет счёт, средства и условия перед открытием. | Доп.: параметры могут измениться после подачи. |
| **U** | **Удобство использования** | |
| U1 | Новые экраны соответствуют дизайн-системе банка. | Условие задания. |
| U2 | Интерфейс различает принятие заявки и открытие депозита. | Доп.: в MVP обработка ручная. |
| U3 | Формы читаемые, с понятными подписями и ошибками. | Доп.: важно для старшей аудитории. |
| **R** | **Надёжность** | |
| R1 | Работа 24/7, доступность 99,9%. | Условие задания. |
| R2 | При отказе ЦОД сервисы переключаются на резервную площадку. | Проверить запас мощности и восстановление данных. |
| R3 | Принятые заявки не теряются, повтор сообщения не открывает второй депозит. | Доп.: защита финансовых операций. |
| R4 | При недоступной АБС заявка ожидает обработки. | Доп.: отказ АБС не останавливает приём заявок. |
| R5 | Неотправленное СМС повторяется отдельно от открытия. | Доп.: сбой уведомления не отменяет договор. |
| R6 | Предложение: восстановление до 10 минут без потери принятых заявок при отказе площадки. | Подтвердить возможностями БД и испытаниями. |
| **P** | **Производительность** | |
| P1 | Справочники и онлайн-операции отвечают быстро. | Сейчас отдельные справочники загружаются дольше секунды. |
| P2 | Предложение: 95% чтений ставок — до 300 мс, принятия заявок — до 500 мс. | Без времени доставки СМС; нагрузку согласовать. |
| P3 | Новые сервисы масштабируются горизонтально, запросы распределяются между экземплярами и ЦОД. | Условие задания. |
| P4 | Каталог и приём заявок не вызывают АБС при каждом запросе. | Снизить нагрузку на Oracle. |
| P5 | Предложение: новые ставки появляются онлайн за 5 минут. | Доп.: измеримый критерий актуальности. |
| **S** | **Поддерживаемость** | |
| S1 | Документировать API, события и работу системы. | Для дальнейшего расширения. |
| S2 | Новую функцию разрабатывает команда банка с минимумом изменений ядра подрядчика. | Проверить доступные расширения платформы. |
| S3 | Контролировать ошибки, задержки очередей и актуальность ставок. | Доп.: для поиска проблем. |
| S4 | Проверять интеграции, нагрузку, отказы и повторы сообщений. | Доп.: подтвердить надёжность до запуска. |
| S5 | Версионировать API/события и предусмотреть откат изменений. | Доп.: системы обновляют разные команды. |
| **+R** | **Ограничения** | |
| +R1 | Использовать знакомые банку технологии и СУБД. | Java, .NET, PHP/React, MS SQL, Oracle. |
| +R2 | Для очередей предпочесть Kafka; подключать её через новые сервисы. | Старый интернет-банк Kafka не поддерживает. |
| +R3 | Шифровать трафик и проверять доступ к персональным данным. | HTTPS; персональные ставки — только своему клиенту. |
| +R4 | Не давать бэк-офисам доступ к исходным данным друг друга. | Условие безопасности из задания. |
| +R5 | Не менять СМС-модуль ядра интернет-банка. | Новый функционал — в сервисе команды банка. |
| +R6 | Не расширять прямой доступ интернет-банка к Oracle; АБС масштабируется только вертикально. | Ограничение текущей платформы. |
| +R7 | Нового клиента с сайта идентифицируют в отделении. | Правило кейса. |
| +R8 | Предложение: СМС-код одноразовый, действует 5 минут, до 5 попыток. | Доп.: защита от повторного использования и перебора; связать код с условиями заявки. |
| +R9 | Счета и договоры ведутся в АБС; ставки имеют версию и срок действия. | Доп.: избежать противоречий между системами. |
| +R10 | Ограничить хранение/доступ к Ф. И. О. и телефону, исключить их из технических логов. | Доп.: защита данных новых клиентов. |

Автоматическое открытие без бэк-офиса — цель на год. Передача ставок кол-центрам описана в [ADR-002](../Task4/ADR-002-rates.md).
